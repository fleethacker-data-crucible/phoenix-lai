## Project
Phoenix LAI (Local LLM Studio): C# (.NET Framework 4.8, compiled in memory by PowerShell 5.1) that runs GGUF models on the GPU through Vulkan compute, with zero third-party dependencies. Two programs: the **Phoenix server** (models on the GPU, OpenAI `/v1` API, tray, dashboard, console) and the **Phoenix Client** (the chat: `html\chat.html` + `html\css`, `html\js`, served by the client on loopback and shown in a Chrome (or Edge) app window; it reaches models only through OpenAI `/v1` providers). No menus: everything is a `/command` (`/help`). Full plan: `.claude/Local LLM Studio (C#) — Development Plan.md`.

## Hardware
- Dev machine: AMD Radeon RX 6700 XT (RDNA2, 12 GB VRAM), Vulkan 1.4 loader at `C:\Windows\System32\vulkan-1.dll`. Has run a 9B model.
- Target machine: HP ZBook laptop, NVIDIA GPU (likely with Intel graphics alongside), 32 GB RAM. Code cannot be changed there: `nvidia\` holds read-only test scripts (`0-unsafe-check.ps1`, `1-check.ps1`, `2-probe.ps1` + `Probe.cs`, `3-collect.ps1`) and `NVIDIA.md`; `.claude` is never copied to production, so `nvidia\tests` holds copies of `KernelTests.cs` + `GemmaGate.cs` and `nvidia\ref` the Gemma `gemma-logprobs.tsv` references (re-copy them when the originals change); the user brings back one zip and fixes are made here. GPU profile (`/settings` -> dev: GPU, `%LOCALAPPDATA%\LocalLLMStudio\gpu-profile.txt`, env `PHOENIX_GPU_PROFILE` / `PHOENIX_GPU_SAFE`): auto|amd|nvidia (+ safe = no subgroup arithmetic / integer dot); nvidia prefers vendor 0x10DE and halves layers per GPU submit.

## Hard rules (never break)
- **No third-party code.** No NuGet `PackageReference`, `Reference`, or `NativeLibrary` entries. BCL only.
- **No network.** No `System.Net`, `HttpClient`, `Socket`, `WebRequest`, or `Process.Start`. No downloads, telemetry, or URL fields in the UI (except a provider's base URL, below). Models load from local paths only.
- **Single exception (approved 2026-10-15): loopback chat server.** Only `src/WebServer.cs` may use `System.Net.HttpListener` (bound to `http://127.0.0.1` only, never outgoing) and `Process.Start` (only to open `chrome.exe --app` or `msedge.exe --app`: settings Auto (default: Chrome, else Edge), Chrome or Edge; approved 2026-10-15). It rejects foreign `Host`/`Origin` headers and serves only files inside `html\`. `run.ps1` enforces this; `html\` may not reference external URLs.
- **Model never runs a shell** (`src/ShellGuard.cs`, enforced by `run.ps1`): its only tools are list/read/edit/write/delete (edit = find/replace in place; delete moves the file into `.llm-backup`; approved 2026-10-16); command tags are refused; no executable files; asked to run something, the model gives the command for the user to run; a 3rd run request within an hour gets a warning (red flashing WARNING banner), a 6th stops all chat input for 5 min (`ShellGuard.CheckRunRequest`); the lockout survives restarts (two HMAC-signed files in `%LOCALAPPDATA%\LocalLLMStudio` and `%APPDATA%\PhoenixLAI`, no registry) and `run.ps1` refuses to start if the guard is removed or unhooked.
- **Project jail:** `/folder` only opens subfolders of `%USERPROFILE%\Phoenix_Projects` (created at startup, hard-coded), given as `/project/sub`; absolute paths, `..` and junctions are refused.
- **API server (approved 2026-10-16):** `src/WebServer.OpenAi.cs` serves the OpenAI-compatible API on `http://localhost:1234/v1` (LM Studio paths: `/v1/models`, `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`), loopback only, no process starts, no RAG. Tool calling (`src/ApiTools.cs`): request `tools` go into the prompt and `<tool_call>` replies come back as OpenAI `tool_calls`; the server never runs a tool (the client does). `/v1/completions` with `suffix` = code completion (FIM tokens if the model has them, else an instructed chat completion).
- **Server / client split (approved 2026-10-20; fully separate 2026-10-21):** two separate programs, never one process. The **server** only exposes the local models as an OpenAI API on `localhost:1234/v1` and knows nothing of the client (no client endpoints, no client launch, no all-in-one mode); the **client** is a plain OpenAI `/v1` client for any added provider, and the Phoenix server is just one of them: the server being offline affects the client only by greying out the Phoenix Local Server (red) in Providers (and docs search falling back to keywords). `src\run-phoenix-server.ps1` (`run.ps1 -Role Server`, `ServerHost.cs`, `TrayPanel.cs`) runs the models and the `/v1` API with no chat window; the tray icon opens a mini dashboard (Start/Stop, Restart, Console, Dashboard, Exit); `html\dashboard.html` + `console.html` (`WebServer.Dashboard.cs`: `/api/server-status`, `/api/console`, Phoenix commands only, never a shell). The server's port 8765 serves only the dashboard and console (no chat page, no folder tools, no RAG). `src\run-phoenix-client.ps1` (`run.ps1 -Role Client` = `WebServer` with `IsClient`, ports 8790-8799) is the **Phoenix Client**: the chat page with every feature (projects + file tools, docs search, skills, code check, compact, run guard) running in the client process, its model calls going to the active provider through `IChatModel` (`ChatModel.cs`; `RemoteChatModel` in `Providers.cs`) and docs-search embeddings to the Phoenix server's `/v1/embeddings` (`RemoteEmbedder`, keyword-only when it is off). Dropped there (they need the server's KV cache): Instant Recall, answer-while-typing, and the server's GPU settings (commented out). When the client's back end stops, its window blurs and shows a dialog with Exit only (start `Phoenix_Client.lnk` again and the open window is adopted and reloads by itself); nothing restarts it from the server.
- **Providers (approved 2026-10-20):** the client may reach **any OpenAI `/v1` provider by URL: this PC, the LAN or the internet** (Providers list at the bottom of the left panel, + to add: name, base URL, API key, models loaded from the provider's own `/models`). Only `src\Providers.cs` makes outgoing requests, all through `Outgoing` -> `WebRequest.Create(CheckTarget(...))`: http/https only, no user:password in the URL, redirects never followed, TLS 1.2+; `run.ps1` rule 4c checks this and refuses outgoing requests in any other file. API keys go to Windows Credential Manager (`CredStore.cs`, WinRT PasswordVault by reflection, resource `PhoenixLAI.Connections`), never to `providers.json` or back to the page, and only to their own provider. Local context (retrieved docs chunks, syntax sheets, RULES.md, project-index matches, files the model reads, skills) goes only to a provider that allows it (`Provider.SendsLocalContext`; approved 2026-10-21: for now only the Phoenix Local Server, the toggle in other providers' windows is off and greyed out). Every other provider gets only the system prompt and what the user types, with no file tools (`WebServer.PrepareMessages`, `LocalContextAllowed`). The server's `/v1` API key is optional (console `apikey new|set|off`, Credential Manager `PhoenixLAI.Server`; off by default because the VS Code extension sends none). Tests use the Phoenix server only, never llama.cpp (a dev reference for comparing outputs). `run.ps1` with no `-Role` runs the client. QA: `.claude\claude_tests\openai-compat.py` (OpenAI Python SDK), `client-qa.py` (providers, keys), `client-e2e.py` (the client's features on a provider).
- **VS Code extension:** `vscode-ext-source\` (plain JS, VS Code API + Node `http` only, no npm, no settings): a Phoenix LAI activity-bar view that embeds the Phoenix Client's chat page (iframe to `127.0.0.1:8790-8799`) and connects the client to the open VS Code folder when it is inside `Phoenix_Projects`, plus inline completion via `127.0.0.1:1234`. `vscode-ext-source\build.ps1` packs `vscode-ext\phoenixlai-<ver>.vsix` (PS 5.1 zip, no vsce).
- **P/Invoke allowlist:** `vulkan-1.dll` and `kernel32.dll` only. Never bundle or download Vulkan; use the driver-installed loader.
- **GPU kernels are SPIR-V** emitted by the in-repo C# `SpirvBuilder`, loaded via `vkCreateShaderModule`. No Vulkan SDK, glslc, or shader compiler DLLs. Baseline Vulkan 1.2 / SPIR-V 1.5; query optional features and fall back.
- No `.dll` files in the repo; no `Assembly.Load*` or `NativeLibrary`.

## Build
- **Production machine:** no installs, no SDK, nothing external; only PowerShell 5.1 + the driver's `vulkan-1.dll`. Phoenix must run there as-is.
- **Dev machine (this one):** dev/reference tools are allowed (e.g. llama.cpp to generate reference outputs, internet for specs). None of them may become a runtime dependency of Phoenix.
- **Entry points:** `Phoenix_Client.lnk` (the client) and `Phoenix_LAI_Server.lnk` (the server), in the root -> `conhost --headless` -> `src\run-phoenix-client.ps1` / `run-phoenix-server.ps1` -> `src\run.ps1`, no windows; it finds the project from the shortcut's own path, so the folder can live anywhere. Recreate it with `.claude\tools\make-shortcut.ps1`. No VBS/HTA/JS launchers.
- **Windows PowerShell 5.1 only** (target machine has no PS7). `src\run.ps1` runs the locality checks, then compiles `src\*.cs` in memory via `Add-Type` with `CompilerParameters` (`/unsafe /optimize+`), then calls the entry point on an STA thread.
- Compiler is .NET Framework 4.8 CodeDom: **C# 5 only**. No `=>` members, `$""`, `?.`, `nameof`, tuples, `Span<T>`, `stackalloc` outside unsafe, `System.Numerics.Vector`, or `System.Runtime.Intrinsics`. CPU code is scalar + `Parallel.For` + unsafe pointers.
- Never compile or test under PowerShell 7 (`pwsh`). Always invoke `powershell.exe` (5.1) explicitly, e.g. `powershell.exe -NoProfile -STA -File src\run.ps1`, even when the shell tool itself is pwsh.
- No project file, no `dotnet`. Each run is a fresh `powershell -NoProfile -STA -File src\run.ps1` (Add-Type types can't reload).
- Root holds only `Phoenix_Client.lnk` (client), `Phoenix_LAI_Server.lnk` (both relative, from `.claude\tools\make-shortcut.ps1 -Script <src script> -Name <lnk>`), `CLAUDE.md`, `__version.info` (the one app version, read by `WebServer.AppVersion` for server, client and pages), `.gitignore` and folders (`src`, `html`, `models`, `logs`, `docs`, `skills`, `nvidia`, `vscode-ext-source`, `vscode-ext`). Phoenix scripts live in `src\`.

## Modules
`Gguf` (memory-mapped parse) · `Tokenizer` (BPE/SentencePiece) · `Vulkan` (DllImport bindings) · `Kernels` (SPIR-V: dequant+matvec, RMSNorm, RoPE, softmax, attention, SiLU, add/mul) · `CpuRef` (scalar/parallel ground truth + fallback) · `GemmaGpu` / `GemmaCpu` (Gemma 4 forward pass, KV cache in VRAM) · `Sampler` · `Engine` (Gemma 4 chat template, KV reuse) · `WebServer` + `Workspace` + `ChatLog` (server: engine, `/v1`, dashboard; client (`IsClient`, `WebServer.Client.cs`): chat API, folder tools, session logs) · `Providers` + `ChatModel` (client: OpenAI `/v1` providers, `RemoteChatModel`, `RemoteEmbedder`) · `Rag` (docs\ library: `/index` builds the incremental BM25 index `docs\.index\rag.bin`, memory-mapped, re-chunks any file whose SHA-256 changed; top chunks go into the newest user message. Syntax sheets: `docs\code-syntax\<language>[-<version>].md` (csharp, power-shell-5.1, power-shell-7, oracle-sql, sql, duckdb-sql, javascript, vbscript, excel-vba, cmd, dax, power-query, qlik-script, excel-formulas, html, css): `## Essentials` card (target version, never → instead table; at most 2,400 chars = one chunk, sent first with every request in that language), `## Recipes` (task-worded, verified examples), then rules and `###` reference entries. A code request searches only its language's sheet, and only the version it names (else the oldest: PS 5.1). Recipes live in `.claude\tools\sheet-parts\` (+ `ps-essentials-{5,7}.md`), merged by `splice-sheet-parts.py`; PowerShell sheets are generated by `make-ps-syntax.py`; check examples with `verify-syntax-docs.py`; measure with `.claude\claude_tests\rag-eval\` (RAG off / old / new sheets, scored by real tools)) · `CodeCheck` + `CodeLint` (deterministic checks on the model's code before it is shown: C# 6+ syntax and .NET Core-only APIs for C# 5 / .NET 4.8 (with automatic C# 5 rewrites), PS 7-only syntax and unknown commands / parameters (`docs\checkers\ps51-commands.tsv` / `ps7-commands.tsv`, from `.claude\tools\make-ps-commands.ps1`), SQL dialect mistakes, VBScript / VBA / CMD / DAX / M / Qlik / Excel / HTML / CSS rules; findings go back to the model as exact fixes, up to two rounds; false-alarm tests: `.claude\claude_tests\codecheck-sheets.ps1`, `codecheck-test.ps1`) · `ProjectIndex` (live index of the active project in `<project>\.phoenix\index`: per-file keyword updates in ms on every save (model writes + FileSystemWatcher), vectors embedded in the background only while the chat is idle; matches go into the newest user message; bench: `.claude\claude_tests\project-index-bench.ps1`) · `Skills` + `WebServer.Skills.cs` (Agent Skills format: `<name>\SKILL.md` with `name`/`description` frontmatter + Markdown body, optional supporting `.md`/`.txt` files; app skills in `skills\`, project skills in `<project>\.phoenix\skills`; the catalog goes into the system prompt, matched or `/name`-called skills in front of the newest user message, matched on the user's own text only; Skill Builder UI `html\js\skills.js` with model-assisted drafting via `/api/skill-assist`) · `StayAwake` (keeps the displays awake during indexing and Instant Recall: a display power-down in the middle of GPU load left the screens black on 2026-10-17) · `Dbg` in `ChatLog.cs` (`/debug on|off`, kept in `%LOCALAPPDATA%\LocalLLMStudio\debug.txt`: every step plus every first-chance exception as `[debug ...]` lines in the session log) · `html\chat.html` (UI).
