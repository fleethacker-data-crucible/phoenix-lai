## Project
Phoenix LAI (Local LLM Studio): C# (.NET Framework 4.8, compiled in memory by PowerShell 5.1) that runs GGUF models on the GPU through Vulkan compute, with zero third-party dependencies. UI: `html\chat.html` (+ `html\css`, `html\js`) served by the loopback server and shown in a Chrome (or Edge) app window. No menus: everything is a `/command` (`/help`). Full plan: `.claude/Local LLM Studio (C#) — Development Plan.md`.

## Hardware
- Dev machine: AMD Radeon RX 6700 XT (RDNA2, 12 GB VRAM), Vulkan 1.4 loader at `C:\Windows\System32\vulkan-1.dll`. Has run a 9B model.
- Target machine: HP ZBook laptop, NVIDIA GPU (likely with Intel graphics alongside), 32 GB RAM. Code cannot be changed there: `nvidia\` holds read-only test scripts (`0-unsafe-check.ps1`, `1-check.ps1`, `2-probe.ps1` + `Probe.cs`, `3-collect.ps1`) and `NVIDIA.md`; `.claude` is never copied to production, so `nvidia\tests` holds copies of `KernelTests.cs` + `GemmaGate.cs` and `nvidia\ref` the Gemma `gemma-logprobs.tsv` references (re-copy them when the originals change); the user brings back one zip and fixes are made here. GPU profile (`/settings` -> dev: GPU, `%LOCALAPPDATA%\LocalLLMStudio\gpu-profile.txt`, env `PHOENIX_GPU_PROFILE` / `PHOENIX_GPU_SAFE`): auto|amd|nvidia (+ safe = no subgroup arithmetic / integer dot); nvidia prefers vendor 0x10DE and halves layers per GPU submit.

## Hard rules (never break)
- **No third-party code.** No NuGet `PackageReference`, `Reference`, or `NativeLibrary` entries. BCL only.
- **No network.** No `System.Net`, `HttpClient`, `Socket`, `WebRequest`, or `Process.Start`. No downloads, telemetry, or URL fields in the UI. Models load from local paths only.
- **Single exception (approved 2026-10-15): loopback chat server.** Only `src/WebServer.cs` may use `System.Net.HttpListener` (bound to `http://127.0.0.1` only, never outgoing) and `Process.Start` (only to open `chrome.exe --app` or `msedge.exe --app`: settings Auto (default: Chrome, else Edge), Chrome or Edge; approved 2026-10-15). It rejects foreign `Host`/`Origin` headers and serves only files inside `html\`. `run.ps1` enforces this; `html\` may not reference external URLs.
- **Model never runs a shell** (`src/ShellGuard.cs`, enforced by `run.ps1`): its only tools are list/read/edit/write/delete (edit = find/replace in place; delete moves the file into `.llm-backup`; approved 2026-10-16); command tags are refused; no executable files; asked to run something, the model gives the command for the user to run; a 3rd run request within an hour gets a warning (red flashing WARNING banner), a 6th stops all chat input for 5 min (`ShellGuard.CheckRunRequest`); the lockout survives restarts (two HMAC-signed files in `%LOCALAPPDATA%\LocalLLMStudio` and `%APPDATA%\PhoenixLAI`, no registry) and `run.ps1` refuses to start if the guard is removed or unhooked.
- **Project jail:** `/folder` only opens subfolders of `%USERPROFILE%\Phoenix_Projects` (created at startup, hard-coded), given as `/project/sub`; absolute paths, `..` and junctions are refused.
- **API server (approved 2026-10-16):** `src/WebServer.OpenAi.cs` serves the OpenAI-compatible API on `http://localhost:1234/v1` (LM Studio paths: `/v1/models`, `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`), loopback only, no process starts, no RAG. Tool calling (`src/ApiTools.cs`): request `tools` go into the prompt and `<tool_call>` replies come back as OpenAI `tool_calls`; the server never runs a tool (the client does). `/v1/completions` with `suffix` = code completion (FIM tokens if the model has them, else an instructed chat completion).
- **VS Code extension:** `vscode-ext-source\` (plain JS, VS Code API + Node `http` only, no npm, no settings): a Phoenix LAI activity-bar view that embeds the studio chat page (iframe to `127.0.0.1:8765`) and connects the studio to the open VS Code folder when it is inside `Phoenix_Projects`, plus inline completion via `127.0.0.1:1234`. `vscode-ext-source\build.ps1` packs `vscode-ext\phoenixlai-<ver>.vsix` (PS 5.1 zip, no vsce).
- **P/Invoke allowlist:** `vulkan-1.dll` and `kernel32.dll` only. Never bundle or download Vulkan; use the driver-installed loader.
- **GPU kernels are SPIR-V** emitted by the in-repo C# `SpirvBuilder`, loaded via `vkCreateShaderModule`. No Vulkan SDK, glslc, or shader compiler DLLs. Baseline Vulkan 1.2 / SPIR-V 1.5; query optional features and fall back.
- No `.dll` files in the repo; no `Assembly.Load*` or `NativeLibrary`.

## Build
- **Production machine:** no installs, no SDK, nothing external; only PowerShell 5.1 + the driver's `vulkan-1.dll`. The studio must run there as-is.
- **Dev machine (this one):** dev/reference tools are allowed (e.g. llama.cpp to generate reference outputs, internet for specs). None of them may become a runtime dependency of the studio.
- **Entry point:** `PhoenixLAI_App.lnk` (root) -> `conhost --headless` -> `src\run.ps1`, no windows; it finds the project from the shortcut's own path, so the folder can live anywhere. Recreate it with `.claude\tools\make-shortcut.ps1`. No VBS/HTA/JS launchers.
- **Lifecycle** (`TechStack` "Lifecycle rules"; `src\Presence.cs`, `src\WebServer.Lifecycle.cs`): the app window posts `/api/heartbeat` every 5 s and a leaving beacon on pagehide; the server stops 20 s after the last heartbeat (75 s for a minimized window), or 5 s after leaving, but never while a reply, model load, indexing or Instant Recall runs. End session = sidebar button or `/quit`. `src\Stop-Phoenix.ps1` stops every running server (runtime files `logs\phoenix-server-<pid>.json`, then a `run.ps1` command-line scan; helpers in `src\Phoenix-Process.ps1`). `run.ps1 -Replace` / `--replace` stops a running server without asking, `-Stay` / `--stay` (or `PHOENIX_AUTO_STOP=0`, or `0` in `%LOCALAPPDATA%\LocalLLMStudio\auto-stop.txt`) keeps it up after the window closes. Test: `.claude\claude_tests\lifecycle-test.ps1`.
- **Windows PowerShell 5.1 only** (target machine has no PS7). `src\run.ps1` runs the locality checks, then compiles `src\*.cs` in memory via `Add-Type` with `CompilerParameters` (`/unsafe /optimize+`), then calls the entry point on an STA thread.
- Compiler is .NET Framework 4.8 CodeDom: **C# 5 only**. No `=>` members, `$""`, `?.`, `nameof`, tuples, `Span<T>`, `stackalloc` outside unsafe, `System.Numerics.Vector`, or `System.Runtime.Intrinsics`. CPU code is scalar + `Parallel.For` + unsafe pointers.
- Never compile or test under PowerShell 7 (`pwsh`). Always invoke `powershell.exe` (5.1) explicitly, e.g. `powershell.exe -NoProfile -STA -File src\run.ps1`, even when the shell tool itself is pwsh.
- No project file, no `dotnet`. Each run is a fresh `powershell -NoProfile -STA -File src\run.ps1` (Add-Type types can't reload).
- Root holds only `PhoenixLAI_App.lnk`, `CLAUDE.md`, `.gitignore` and folders (`src`, `html`, `models`, `logs`, `docs`, `skills`, `nvidia`, `vscode-ext-source`, `vscode-ext`). Studio scripts live in `src\`.

## Modules
`Gguf` (memory-mapped parse) · `Tokenizer` (BPE/SentencePiece) · `Vulkan` (DllImport bindings) · `Kernels` (SPIR-V: dequant+matvec, RMSNorm, RoPE, softmax, attention, SiLU, add/mul) · `CpuRef` (scalar/parallel ground truth + fallback) · `GemmaGpu` / `GemmaCpu` (Gemma 4 forward pass, KV cache in VRAM) · `Sampler` · `Engine` (Gemma 4 chat template, KV reuse) · `WebServer` + `Workspace` + `ChatLog` (loopback chat API, folder tools, session logs) · `Rag` (docs\ library: `/index` builds the incremental BM25 index `docs\.index\rag.bin`, memory-mapped, re-chunks any file whose SHA-256 changed; top chunks go into the newest user message. Syntax sheets: `docs\code-syntax\<language>[-<version>].md` (csharp, power-shell-5.1, power-shell-7, oracle-sql, sql, duckdb-sql, javascript, vbscript, excel-vba, cmd, dax, power-query, qlik-script, excel-formulas, html, css): `## Essentials` card (target version, never → instead table; at most 2,400 chars = one chunk, sent first with every request in that language), `## Recipes` (task-worded, verified examples), then rules and `###` reference entries. A code request searches only its language's sheet, and only the version it names (else the oldest: PS 5.1). Recipes live in `.claude\tools\sheet-parts\` (+ `ps-essentials-{5,7}.md`), merged by `splice-sheet-parts.py`; PowerShell sheets are generated by `make-ps-syntax.py`; check examples with `verify-syntax-docs.py`; measure with `.claude\claude_tests\rag-eval\` (RAG off / old / new sheets, scored by real tools)) · `CodeCheck` + `CodeLint` (deterministic checks on the model's code before it is shown: C# 6+ syntax and .NET Core-only APIs for C# 5 / .NET 4.8 (with automatic C# 5 rewrites), PS 7-only syntax and unknown commands / parameters (`docs\checkers\ps51-commands.tsv` / `ps7-commands.tsv`, from `.claude\tools\make-ps-commands.ps1`), SQL dialect mistakes, VBScript / VBA / CMD / DAX / M / Qlik / Excel / HTML / CSS rules; findings go back to the model as exact fixes, up to two rounds; false-alarm tests: `.claude\claude_tests\codecheck-sheets.ps1`, `codecheck-test.ps1`) · `ProjectIndex` (live index of the active project in `<project>\.phoenix\index`: per-file keyword updates in ms on every save (model writes + FileSystemWatcher), vectors embedded in the background only while the chat is idle; matches go into the newest user message; bench: `.claude\claude_tests\project-index-bench.ps1`) · `Skills` + `WebServer.Skills.cs` (Agent Skills format: `<name>\SKILL.md` with `name`/`description` frontmatter + Markdown body, optional supporting `.md`/`.txt` files; app skills in `skills\`, project skills in `<project>\.phoenix\skills`; the catalog goes into the system prompt, matched or `/name`-called skills in front of the newest user message, matched on the user's own text only; Skill Builder UI `html\js\skills.js` with model-assisted drafting via `/api/skill-assist`) · `StayAwake` (keeps the displays awake during indexing and Instant Recall: a display power-down in the middle of GPU load left the screens black on 2026-10-17) · `Dbg` in `ChatLog.cs` (`/debug on|off`, kept in `%LOCALAPPDATA%\LocalLLMStudio\debug.txt`: every step plus every first-chance exception as `[debug ...]` lines in the session log) · `html\chat.html` (UI).

## Workflow
- Work phase by phase (see plan roadmap, phases 1–8). Don't start a phase until the previous gate test passes.
- `CpuRef` is ground truth for each op (kernel tests); end to end, the GPU must match llama.cpp's logprobs as closely as `CpuRef` does.
- Tests, benchmarks and llama.cpp reference outputs live in `.claude\claude_tests\` (gates 2–9: `powershell.exe -NoProfile -STA -File .claude\claude_tests\gate.ps1 -Phase N`, default model `models\gemma-4-12b-it-qat-q4_0.gguf`; references in `ref\outputs\<model>\`, regenerated with `ref\make-refs.ps1` and `ref\make-gemma-logprobs.ps1`; prefill speed: `pfbench.ps1`), plus self-checks (round-trips, GPU vs `CpuRef`).
- **Gemma 4 only** (chat: `gemma-4-12b-it-qat-q4_0.gguf`; docs search: `embeddinggemma-2-Q8_0.gguf`). Llama / Mistral support was removed 2026-10-17; other architectures are refused at load.
